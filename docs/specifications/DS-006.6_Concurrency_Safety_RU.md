# DS-006.6 — Concurrency & Safety
**Статус:** granularity/duration locks утверждены; механизм реализации открыт.

## Утверждённое правило
На время DeploymentExecution захватываются блокировки по **Component + Environment** для всех компонентов, над которыми будут производиться операции, включая внешние компоненты STOP/START. Пока действует блокировка, другой DeploymentExecution, затрагивающий тот же ключ, не может одновременно выполняться.

## Примеры
- Release X → UAT: A, B; Release Y → UAT: B, C — конфликт B: второй запуск блокируется до освобождения.
- Release Z → UAT: D, E — может идти параллельно, если нет пересекающихся ключей.
- Ключ lock — Component + Environment, не индивидуальный сервер (пока).

## Надёжность
- Блокировка удерживается на всём протяжении исполнения, включая WAITING_FOR_OPERATOR и неопределённость внешних операций.
- Не теряется при рестарте DS или Temporal Worker; освобождение не должно происходить только из-за потери heartbeat/временного сетевого сбоя без достоверного завершения.
- Отсутствие подтверждённого завершения внешней операции не должно преждевременно освобождать lock.
- Конфликты видимы оператору с указанием затронутых компонентов и существующего execution.

## Приёмочные сценарии (проект тестов)
- Два deployment в UAT с пересечением B: только один может начать операции для B.
- Непересекающиеся D/E не блокируются чужим A/B.
- WAITING_FOR_OPERATOR сохраняет блокировки.
- После рестарта worker система не допускает конкурентного запуска в тот же locked key.

## Открыто до реализации
Транзакционный алгоритм атомарного захвата множественных keys, deadlock avoidance, durable lease/reconciliation, crash recovery, порядок lock release и поведение очереди ожидающих запусков; выполнение шагов относится к DS-007.

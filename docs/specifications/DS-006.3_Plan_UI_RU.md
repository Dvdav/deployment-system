# DS-006.3 — Deployment Plan UI
**Статус:** правила UI утверждены; конкретная библиотека DnD и макеты не определены.

## Основной экран
Отображать **фактический порядок операций** (STOP/DEPLOY/START/VALIDATE), компонент, сервер(а), режим (Release/external), целевой artifact, причину шага, предупреждения и блокирующие ошибки. Перед запуском показывать полный проверенный план и операторские подтверждения.

## Перестановка
- Drag & Drop для разрешённых участков последовательности, где перестановка не нарушит dependency ordering, operation prerequisites и целостность шага.
- При недопустимом перемещении отклонить его и объяснить конкретное нарушенное ограничение.
- Независимые компоненты исполняются последовательно по умолчанию, порядок можно выбирать вручную.
- Внутри компонента ALL_AT_ONCE означает параллельный запуск необходимых серверных операций — это не разрешение вручную выбирать подмножество deployment targets.

## Решения оператора
- Отдельно показать внешние затронутые компоненты и разрешить включить STOP/START либо исключить их с причиной/acknowledgment.
- Для неизвестного состояния server operator обязан выбрать STOP → DEPLOY или DEPLOY без STOP и указать причину.
- Force Redeploy по отдельному серверу сопровождается явным выбором и причиной.
- Snapshot утверждённого DeploymentPlan сохраняет порядок, выборы, предупреждения, метаданные конфигурации без секретов.

## Приёмочные сценарии (проект тестов)
- DnD независимых A, B меняет фактический порядок.
- DnD зависимого A перед B (A → B) блокируется там, где это нарушит план.
- Неподтверждённое предупреждение/UNKNOWN target не позволяет запустить план.

## Открыто
UX при большом числе инстансов, показ групп операций, блокирующие сообщения по изменившимся контрактам и механизм сохранения draft plan.

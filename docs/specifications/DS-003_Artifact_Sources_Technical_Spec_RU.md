# DS-003 — Artifact Sources

Статус: согласованные требования и явно отмеченные открытые вопросы. Зависимость: DS-002.

## Scope
ArtifactSource — Java-интерфейс; NexusRepository — первая реализация. Использовать существующий UUID и конфигурацию nexus_repository из DS-002; отдельной таблицы artifact_source нет. Сетевые операции вынести в сервис, не в persistence entity. Credentials принадлежат NexusConnection. Регистрацию, классификацию, архивирование и восстановление не дублировать.
Операции: поиск Maven-артефактов, получение версий, метаданных и checksum/идентичности asset, проверка доступности, разрешение конкретной SNAPSHOT-сборки. Скачивание файлов не входит в scope. Nexus — источник актуальных данных, без локального каталога, фоновой синхронизации и кэша в MVP.

## Поиск и версии
По artifactId определять найденные groupId; единственное совпадение выбирать автоматически, неоднозначность разрешает оператор. Сохранять обе Maven-координаты; после регистрации компонента они неизменяемы. Запрашивать привязанные активные репозитории параллельно. Возвращать RELEASE и SNAPSHOT вместе, сортировать от новых к старым по времени публикации/создания, доступному в Nexus. Одинаковые версии из разных репозиториев — отдельные записи с repository UUID и названием. Для каждой логической SNAPSHOT-версии показывать только последнюю сборку в каждом репозитории. При частичной недоступности возвращать доступные результаты и предупреждение с указанием недоступных источников; не выдавать ошибку за пустой успешный результат. Обрабатывать пагинацию Nexus.

## Контракт будущих модулей (не реализация UI в DS-003)
DS-004: Component UUID, artifactId (name), автоматически определяемый groupId, описание, связи M:N с зарегистрированными репозиториями. Координаты неизменяемы; описание и связи редактируемы.
Release Management: autocomplete по локальному Component Registry. При выборе компонента автоматически загрузить версии из Nexus, без кнопки проверки. Поле версии пустое по умолчанию; индикатор загрузки; по клику показать все версии, по вводу автоматически открыть и фильтровать список; вручную сохранять отсутствующую версию нельзя. Защита от запоздавших ответов при смене компонента. Фильтрация на frontend по уже загруженным данным — предложенная реализация. ReleaseComponent хранит componentId, repositoryId и version. READY: состав, версии и источники read-only на UI и backend; изменение через DRAFT с архивированием предыдущего Manifest. ReleaseManifest сохраняет неизменяемый снимок координат, источника и версии.
Deployment: для SNAPSHOT Manifest хранит логическую версию; при новом Deployment определить последнюю конкретную сборку, записать точную идентичность, путь и checksum в Execution; все серверы компонента используют одну сборку; Retry внутри того же Deployment сохраняет эту сборку. Это заменяет прежнее требование фиксации точной SNAPSHOT-сборки при READY. Ограничения SNAPSHOT по окружениям не меняются.

## Открытые вопросы
Обязательность повторных проверок при DRAFT→READY и до STOP при запуске Deployment предложена, но явно не согласована. Механизм проверки входит в DS-003; точки вызова уточнить в будущих задачах. Точный выбор Maven asset при наличии classifier/extension, источник даты и tie-break, API/таймауты, критерий существования при регистрации компонента требуют уточнения. Dependency guards DS-002 расширять по мере появления реальных ссылок в DS-004/Release Management; не создавать фиктивных связей.

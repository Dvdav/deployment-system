# DS-006.2 — Dependency-aware Planning
**Статус:** архитектурные решения утверждены; семантика частичных инстансов и HA ограничена.

## Модель и направление
A → B означает: A зависит от B. На графе ComponentDependency запрещены циклы, self-links, дубли. DS находит прямые и транзитивные обратные зависимости при обновлении B.

## Утверждённое поведение
- STOP зависимых раньше зависимостей; DEPLOY/START/VALIDATE — зависимости раньше зависимых.
- Если Release обновляет только C в цепочке A → B → C, пример плана: STOP A → STOP B → STOP C → DEPLOY C → START C → VALIDATE C → START B → VALIDATE B → START A → VALIDATE A. Отсутствующие необязательные операции опускаются.
- A и B могут быть **внешними** (вне ReleaseManifest): их артефакты не добавляются в Manifest, DEPLOY им запрещён, но с согласия оператора допустимы STOP/START и, если настроена, VALIDATE.
- Если оператор включил внешний компонент во временную остановку, у него обязательно должны быть и STOP, и START DeploymentProfiles; нельзя подменять их DEPLOY.
- DS предлагает затронутые внешние зависимости; оператор может исключить конкретную с предупреждением, обязательной причиной и явным подтверждением. Никаких операций над исключённым компонентом.
- Наличие dependency **не доказывает необходимость перезапуска** при единичном отказе инстанса: оператор учитывает HA/failover, DS не делает автоматических выводов о числе healthy instances.
- При failed STOP план ждёт оператора; после Abort нет автоматического START ранее остановленных компонентов.

## Приёмочные сценарии (проект тестов)
- Транзитивная цепочка обнаружена, порядок STOP противоположен DEPLOY/START.
- Отказ оператора от STOP A без причины блокирует подтверждение; с подтверждением исключает A из операций и фиксируется в аудите.
- Отсутствует STOP или START профиль для включённого внешнего A: блок.
- Версия/Manifest внешнего A не изменяется.

## Не входит в MVP
Автоматическое определение availability/failover, minHealthyInstances и расчёт service topology. Межсерверный rolling без отдельного решения не подменяет текущий ALL_AT_ONCE.

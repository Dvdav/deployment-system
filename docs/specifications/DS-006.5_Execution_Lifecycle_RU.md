# DS-006.5 — Execution Lifecycle & Audit Semantics
**Статус:** правила статусов и ручных решений утверждены; Temporal implementation — DS-007.

## Уровни
DeploymentStep описывает операцию для Component + Environment + Server; результат компонента агрегируется по необходимым targets; DeploymentExecution — общий результат плана, включая внешние зависимости, operator decisions и validations. Успех DEPLOY не равен успеху START/VALIDATE.

## Статусы
- Промежуточные: PENDING, RUNNING, WAITING_FOR_OPERATOR (детальная машина состояний уточняется).
- Терминальные: SUCCEEDED, COMPLETED_WITH_WARNINGS, ABORTED, CANCELLED, FAILED.
- Строгая модель: SUCCEEDED только если все необходимые операции SUCCEEDED или MANUALLY_COMPLETED. SKIPPED/UNKNOWN не дают SUCCEEDED; после обработанного Skip итог при завершении — COMPLETED_WITH_WARNINGS. Неразрешённый UNKNOWN не трактуется как завершение — ожидание/эскалация.
- CANCELLED: оператор отменил до начала первого реального шага. ABORTED: после начала хотя бы одного шага. FAILED: техническая невозможность завершения (детальная классификация открыта).
- MANUALLY_COMPLETED признаётся результатом **конкретной** операции и не подтверждает автоматически соседние операции. Аудит фиксирует who/when/reason.

## Ошибки и действия
- При ошибке дальнейшие новые шаги приостанавливаются до решения оператора.
- Доступны Retry, Skip, Mark as Completed, Abort — действия/причины и исходные результаты сохраняются.
- При Abort никакого автоматического START уже остановленных компонентов, никакого автоматического rollback. Внешние операции, которые уже были запущены, требуют установления фактического outcome или отметки об неопределённости.
- После ABORTED не re-open workflow: новый Execution (см. DS-006.4).

## Immutable audit
Сохраняются plan snapshot, последовательность и результат server-level steps, предыдущие результаты и попытки, decisions и объяснения, пользователи, warnings, задействованные contract revisions/profiles и ссылки на внешний job. Секреты/пароли исключить.

## Проверки
- Skip VALIDATE → нельзя пометить SUCCEEDED; успешная testing-раскатка этого Manifest не должна автоматически считаться доказанной.
- START manually completed → зачёт только START, VALIDATE остаётся отдельной.
- Отмена до первого шага → CANCELLED, после начала → ABORTED.

## Граница
Temporal retry, external job launch/poll/reconnect и отдельная ручная привязка external run ID — DS-007. Точная реакция на «не удалось связаться с источником» и лимиты ожидания подлежат отдельной детализации.

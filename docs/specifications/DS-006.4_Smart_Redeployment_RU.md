# DS-006.4 — Smart Redeployment & Force Redeploy
**Статус:** архитектурные решения утверждены; точная модель state projection открыта.

## Источник истины для MVP
DS использует собственную историю операций как **последнее известное состояние**, НЕ опрашивает серверы для фактической версии. Отдельно для Component + Environment + Server учитываются точный артефакт/asset из Manifest и результаты STOP/DEPLOY/START/VALIDATE. Совпадения строки версии недостаточно для изменяемых SNAPSHOT.

## Построение повторного плана
- Если точный артефакт уже установлен и необходимое рабочее состояние подтверждено, не повторять DEPLOY и сопутствующие STOP/START ради обновления.
- Если на сервере нужен новый артефакт — добавить операции для этого сервера. ALL_AT_ONCE относится только к необходимым серверным операциям.
- Если предыдущий DEPLOY succeeded, но START failed и VALIDATE не выполнялась — новый Execution получает START → VALIDATE без нового DEPLOY.
- SUCCEEDED и MANUALLY_COMPLETED подтверждают **только соответствующую операцию** (ручное вмешательство аудируется); SKIPPED, UNKNOWN, NOT_STARTED и FAILED не подтверждают результат.
- После ABORTED всегда новый DeploymentExecution и вновь построенный план, а не resume завершённого Temporal Workflow.
- Сервер без истории: UNKNOWN, оператор обязательно выбирает STOP → DEPLOY или DEPLOY без STOP, указывает причину; без выбора запуск заблокирован.
- Force Redeploy разрешён на уровне Component + Environment + Server, даже если artifact совпадает. Требуются причина и подтверждение. Он не меняет Manifest; зависимости анализируются как при обычном DEPLOY, и операторы могут исключить внешние зависимые сервисы по обычным правилам.
- Нельзя вручную выбрать произвольную иную версию в DeploymentPlan: менять версии можно только через DRAFT → новый READY Manifest.

## Приёмочные сценарии (проект тестов)
- Из трёх серверов только один не достиг версии 2.1: только он включается в DEPLOY.
- DEPLOY succeeded, START failed: без повтора DEPLOY, но с START и VALIDATE.
- Новый server-02 без истории: запуск требует выбора стратегии STOP и причины.
- Force Redeploy server-01 с совпадающим asset: создаёт операции и dependency warnings, но не меняет Manifest.

## Открыто
Правила разрешения противоречивых или устаревших записей истории, ручных изменений вне DS и алгоритм проекции состояния в случаях STOP/START без DEPLOY.
